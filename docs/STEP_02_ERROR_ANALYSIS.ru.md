# Шаг 2: выясняем, почему область осталась видна

## Что делаем

До замены детектора нужно увидеть, что происходит внутри пайплайна. Приложение сначала ищет прямоугольные области, а затем размывает только найденные области. Поэтому читаемый номер может означать две разные ошибки:

1. **Пропуск детектора (false negative):** рамки вокруг номера нет. Размытие здесь ни при чём — модель не передала приложению область для обработки.
2. **Недостаточный охват или размытие:** рамка есть, но захватывает не весь номер или размытие сохраняет читаемые детали.

Эти ошибки требуют разных улучшений. Низкий порог размытия не исправит пропуск детектора; более сильный детектор не исправит слишком маленькую рамку.

## Как проверить свой ролик

1. Запусти приложение двойным щелчком по `start-app.bat`.
2. Загрузи короткое видео и найди время, где номер хорошо виден.
3. В поле **«Секунда видео для проверки»** укажи это время.
4. Нажми **«Показать найденные области»**.
5. Посмотри на зелёные рамки и счётчики лиц/номеров.

Интерпретация:

- Номер виден, зелёной рамки нет → baseline пропустил объект.
- Рамка захватывает только часть номера → детектор нашёл объект, но локализация недостаточно точная.
- Рамка покрывает весь номер, но результат читается → нужно усилить размытие или расширить область.

Проверочный кадр показывается только в локальном интерфейсе. Не загружай своё видео или кадры с чужими лицами/номерами в GitHub.

## Термины

- **Детектор** — алгоритм, который сообщает, где на кадре находятся объекты.
- **Ограничивающая рамка (bounding box)** — прямоугольник вокруг обнаруженного объекта.
- **False negative (FN), пропуск** — объект есть, но детектор его не нашёл.
- **False positive (FP), ложное обнаружение** — детектор отметил область, где объекта нет.
- **Локализация** — насколько точно рамка совпадает с границами объекта.
- **Постобработка** — действия после детектора. В нашем приложении это расширение рамки и размытие пикселей.

## Что запишем в журнал

Для выбранного кадра отметь:

| Поле | Значение |
|---|---|
| Тип объекта | лицо / номер |
| Время в видео | секунды |
| Рамка найдена | да / нет |
| Рамка покрывает весь объект | да / нет |
| Объект остаётся читаемым после размытия | да / нет |
| Возможная причина | пропуск / малая рамка / слабое размытие |

Это упрощённый ручной анализ ошибки. Позже мы разметим кадры и посчитаем recall: долю реальных объектов, которые детектор нашёл.

## Следующий шаг

После проверки нескольких кадров сравним Haar Cascade с нейросетевым детектором и отдельно решим, нужно ли дообучение. В OpenCV Zoo есть LPD-YuNet, но его авторы указывают, что модель обучена на китайских номерных знаках и может хуже работать с другими форматами. Поэтому прежде чем брать её как решение, мы проверим её на нужном типе номеров или подготовим данные для дообучения. См. [описание модели OpenCV Zoo](https://github.com/opencv/opencv_zoo/tree/main/models/license_plate_detection_yunet).
